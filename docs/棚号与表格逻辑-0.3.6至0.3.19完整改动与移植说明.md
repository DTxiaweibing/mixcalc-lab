# 棚号 / 表格逻辑 —— 0.3.6 → 0.3.19 完整改动记录与移植说明

> 用途：把这一轮所有改动**连同背后的规则和踩过的坑**完整记录下来，便于在一个功能相同的
> HarmonyOS（ArkTS）应用里重做一遍。文中的"规则"是与平台无关的业务不变量；"实现"是 Android 版的做法。
>
> 记录范围：0.3.6（versionCode 9，接手第一版）→ 0.3.20（versionCode 23）。
> 0.3.6 之前的表格绘制、列管理、批次、键盘自适应不属于本轮，不在此文。

---

## 0. 一句话总览

这一轮把"棚号"从一个**自由文本 + 第一行算总数**的粗糙模型，改造成了一个**有唯一权威归属的棚号账本**：

- 每行填的棚号是"**声明**"，不是真相；
- 真相由"**后行优先**"的打点覆盖决定：一个棚号归最后一个声明它的行；
- 每行**显示**的文本 = 它实际拥有的号，所以看到的号永远等于参与算料的号；
- 声明不被覆盖改写，因此后行缩小/清空时，号会**自动退回**上面的行；
- 输入过程每敲一个字符就全表重算，但用"编辑前快照"保证半成品输入不会改坏别人。

## 2. 数据模型

```
FeedData（一行）
  shedNumber   String   声明原文（用户填的 / 转移后的 / 删除后的）。**落盘存这个**
  shedDisplay  String   显示文本（实际拥有）。**不落盘**，每次覆盖计算刷新；null 时回落到 shedNumber
  shedCount    int      有效棚数 = 打点覆盖后归本行的号码个数（唯一权威）
  average              每棚平均吃料（手改过则保持，不随棚数变）
  fermented/powder/feed03/feed05/feed10   五种料
  water / weighedFeed  派生
  switchRatio          换料比例
```

> `shedCountBase` / `shedCountBaseSum` 是 0.3.6 之前"第一行 = 总棚数"时代留下的锚点字段，
> 本轮规则下所有行一视同仁，它们不再参与计算。**新项目不必实现这两个字段。**

```java
getShedDisplay() { return shedDisplay != null ? shedDisplay : getShedNumber(); }
setShedNumber(s) { shedNumber = s; shedDisplay = null; calculateShedCount(); }  // 声明变了，派生显示作废
```

**为什么必须两层**：只要覆盖去改声明，号被占走一次就永久消失，后行再改小也回不来（0.3.12 的真实缺陷）。
拆成两层后，"占走"只是"暂时不归你"，声明还在，随时能退回。

## 3. 核心算法（平台无关，可直接照抄成 ArkTS）

### 3.1 解析 `ShedCoverage.parseShedNumbers(text)`

- 先把区间符号统一成 `-`：`到 至 ~ ～ — －`；再把 `"-"` 两侧的空白去掉。
- 分隔符：`,` `，` `、` `;` `；` `/` 以及任意空白。
- 每段：含 `-` 视为区间，取**前两个**数字；否则取该段所有数字拼成的一个数。
- **兜底**：`start > end` 时交换（所以 `16-4` 会被当成 4~16，这正是 0.3.13 那个坑的由来）。
- `start <= 0` 抬到 1；任一端 `> 1000` 整段丢弃（并由 `findOverLimit` 给提示）；跨度 `> 10000` 整段丢弃。
- 结果去重、升序。

### 3.2 打点覆盖 `ownedSets(texts)` —— 唯一权威

```
owner = {}                      // 号码 → 行下标
for i in 0..n-1:                // 从上往下，后面的覆盖前面的
    for n in parse(texts[i]): owner[n] = i
owned[i] = { n | owner[n] == i }   // 升序
```

`ownedCounts` = 每个 owned 集合的大小。

**铁律**：`shedCount` 只能是这个结果，不能是"本行文本自己数的个数"。所有"料量按棚数重算"的分支都必须在
覆盖之后、并且拿覆盖结果去比。

### 3.3 显示文本 `renormalize(texts)`

对每行：
- `owned` 为空 → 原样返回原文（0 棚行马上要被整行回收，清空会留中间空洞）；
- `owned.size() == parse(原文).size()` → 原样返回（没人抢号，保留用户写法，如 `24-40 1-20`）；
- 否则 → `normalize(owned)`（升序、连号合区间、空格分隔）。

这是**显示**，不是原文。0.3.12 把它写回原文，0.3.14 改成只写 `shedDisplay`。

### 3.4 区间压缩 `normalize(numbers)` / `compress`

- 升序去重；
- **连续 ≥ 3 个**才写成 `a-b`；连续 2 个仍是 `a b`（否则 `1 2` 会被压成 `1-2`，和用户直觉不符）；
- 各项之间用**空格**（`JOINER = " "`），不用 `、`。

### 3.5 转移 `transfer(sourceText, targetText, numbers)`

```
source = set(parse(sourceText)) - numbers
target = set(parse(targetText)) + numbers
return [normalize(source), normalize(target)]
```

按**号码集合换主人**，不做任何"落在目标行跨度里就跳过"的判断。

### 3.6 删除 `remove(text, numbers)`

逐段处理：单号命中直接删；区间段里只要有命中就**拆开**，剩下的重新压缩；一个都没删到则**原样返回**
（连格式都不动）。

```
1 3 5 7 8-40 去 3   → 1 5 7 8-40
1-40     去 5       → 1-4 6-40
10-20    去 15,16   → 10-14 17-20
```

### 3.7 整行转空行拦截 `pointlessWholeRowMove(targetText, sourceOwned, numbers)`

目标行为空 且 待转池包含来源行"实际拥有"的全部号码 → 这次转移等价于把整行下移一格（来源行被回收、
下面整体上移），只会闪屏，直接拒绝并提示。

### 3.8 编辑草稿 `ShedDraft.recompute(snapshot, editingRow, typedText)`

```
base = copy(snapshot)
if editingRow in range: base[editingRow] = typedText
sets   = ownedSets(base)
texts  = renormalize(base)
texts[editingRow] = typedText        // 正在敲的那行永远显示原文，不被规范化
return { texts, counts }
```

`snapshot` = 进入棚号编辑那一刻的全表**声明**文本。每敲一个字符都从快照重推，**不在上一帧结果上累积**。

### 3.9 两行极简显示 `ShedDisplay.render(raw)`

口径：数字、`-`、空格、`…` 各算 1 字符。铁律：

1. 任何连续区间绝不从中间切断；
2. 每行 ≤ 9 字符，最多 2 行，任何情况不爆行；
3. 省略号只在真的截断时出现，无信息丢失绝不出现；
4. 必须截断时优先露出首、尾两个关键区间（`1…3-15`、`…25-32`）。

分支（命中即返回）：`A-1` 单行全显示 → `A-2` 两行全显示 → `B-1` 散点截断 → `B-2` 双区间紧凑折叠。
只用于**展示态**；点进格子编辑时加载完整原文。

### 3.10 行回收 `RowSettlement`

- `recycleDeadRows(rows, emptiedByUser)`：**有内容**（声明非空或填过数据）且**有效棚数 = 0** → 整行移除；
  纯空行绝不删（那是留给用户录入的容量）；判定必须在清数据之前做，否则"只有数据没有棚号"的脏行会漏成中间空洞。
- `settleZeroRows(rows)`：兜底，把仍然 0 棚却留着数据的行清成新行（棚号保留）。
- ⚠️ **有效棚数必须按声明文本重算**（`ShedCoverage.ownedCounts`），不能读 `FeedData.getShedCount()` 缓存：
  缓存可能还没刷新，几行同时被下面一行覆盖时这一轮只认出一个死行，其余要等下次操作才删，
  用户看到的就是"键盘按一下进一行、再按一下再进一行"。以文本为准，一次扫全表就能全部认出来。
- `emptiedByUser`：本次被用户删空（棚号删到一点不剩）的行下标。这种行文本为空、数据为空，
  按纯空行规则会保留，必须强制回收，否则表中间留洞。只放真被掏空的行，别塞纯空行。
- 只在**结算时刻**调用（换格收起、切批次、退出、载入），编辑途中绝不删行。
- 一次结算必须把**所有**该删的行一起删：不要"先删转空的行、下一帧再删其余死行"，
  那会让用户看到分两批上移。
- 编辑途中的 0 棚行只做"**隐藏但保留**"：五种料列置灰且不显示任何数字，平均/水/称料留纯空白；
  底层数据不动，棚数改回 >0 立刻恢复显示。真正清数据只发生在结算。

## 4. 运行时：状态机与数据流

### 4.1 单一提交出口

```
CellEditorOverlay（全表只有一个 EditText 浮层）
  TextWatcher(每字符) / commitInternal →
    Activity.onCellCommitted(row, col, text)
      → commitCell(row, col, text)          // 写模型：棚号→setShedNumber；料列→setXxx
      → applyRowChange(row)
           ├ applyShedCoverage()            // 打点覆盖 → 写 shedDisplay + 修正 shedCount + 重算派生
           ├ data.updateAllCalculations()   // 本行派生值
           ├ table.notifyAllChanged()
           ├ updateFooterRow()
           └ saveAllData()                  // 存的就是声明
      → onCellEditEnd → table.post(settleZeroRows)   // 延后，避免与换格冲突
```

### 4.2 编辑生命周期（棚号格）

```
beginEdit
  editingShedNumber = true
  shedEditRow = row
  shedEditSnapshot = [每行 getShedNumber()]     // 声明快照

每字符 commitCell
  setShedNumber(typed)                          // 只影响这一行的声明
  applyShedCoverage()
     liveTyping == true → ShedDraft.recompute(snapshot, shedEditRow, typed)
     其余行：texts 来自快照 → 别人的显示/棚数/料量实时跟着变
     编辑行：显示 = typed，不被规范化

end
  editingShedNumber = false
  shedEditSnapshot = null；shedEditRow = -1     // 必须先清，再做定稿这一遍
  applyRowChange(row)                           // 用最终文本把全表钉一遍
  table.post(settleZeroRows)
```

### 4.3 待转池生命周期（纯内存）

```
转出：pendingTransferNumbers = 选中号码；pendingTransferSourceRow = 行号；关气泡（豁免一次 dismiss 清理）
     → 来源行数据一个字不动
作废：dispatchTouchEvent 的 ACTION_DOWN（除非落在另一行的 shed_count 格）、气泡 dismiss、
      onPause、窗口尺寸变化、切批次、行回收
转入：只有"另一行的气泡 → ⋮ → 转入"才执行
```

### 4.4 转入流程

```
1 校验：池子非空、目标行 ≠ 来源行
2 防呆：整行转空行 → toast 拒绝
3 transfer(声明) → [新来源文本, 新目标文本]
4 clearPendingTransfer()
5 commitCell(来源, 新来源文本) → commitCell(目标, 新目标文本)
6 rewriteToOwned(来源)、rewriteToOwned(目标)    // 钉成各自实际拥有，清幽灵号
7 forceRecomputeRows(来源, 目标)                // 强制重算，不依赖变更检测
8 一次算出所有该回收的行（被转空的两行 + 幽灵号清掉后露出的死行）→ 一次回收 + 补空行
```

### 4.5 删除流程（0.3.15 起：有地方退就退）

```
删除 = "这几个棚不要了"
本行申明 = remove(本行申明, 号码)      // 只动本行，绝不遍历全表
applyRowChange(row)                    // 覆盖 + 派生一起重算
if 本行申明为空 && 本行有效棚数 = 0:
    post(settleZeroRows(emptied = {row}))   // 整行销毁 + 底部补空行 + 下面行上顶
```

为什么"只删本行"就同时满足两种语义：

- **有地方退就退**：本行拥有的号如果上面某行还申明着（本来就是从那儿退下来的），
  从本行申明剔掉之后，覆盖重算时没有本行占着了，号立刻回到上面那行继续算料；
- **没地方退就等于删除**：别的行都没申明过它，本行剔掉就是全表真的没有了。

⚠️ 0.3.14 曾把删除改成"遍历全表一起剔"，理由是"只删本行的话上面那行还声明着，号码会复活"。
那是把"退回"当成了 bug。按最终确认的业务语义，**退回是正确的**，只有确实无人认领时才算卖掉。
移植时请按本节实现。

⚠️ 删空的行必须显式回收：这一行此刻既没有棚号文本、也没有数据，按"纯空行=录入容量"的规则
会被留下来，表中间出现一个洞、下面的行也不上顶。所以 `recycleDeadRows` 增加 `emptiedByUser`
参数，只回收"本次被用户掏空"的行（下标由调用方传入），其余纯空行照旧保留。

### 4.6 删除确认：把"真删的号"点名（`ShedDeletePlan`）

删除在用户看来是同一件事，实际有两种后果，确认框必须说清楚，否则用户以为只是"挪个位置"：

| 情况 | 判定 | 确认框要说什么 |
|---|---|---|
| 有来路 | 本行**上方**某行申明过这个号 | 会退回那一行继续算料，不会消失 |
| 没有来路 | 上方没有任何行申明过它 | 全表都不会再有，**把号码列出来** |

判定逻辑（纯函数，与 UI 无关，建议原样移植）：

```
for n in 选中的号:
    if 存在 i < row 且 parse(第i行申明) 包含 n:  fallback.add(n)   // 有来路
    else:                                        permanent.add(n)  // 真删
```

- 只看**上方**：本行显示的号一定是本行申明里、且没被下面行占走的号，所以不可能同时被下面的行申明。
- 三种文案：全可退 / 全不可退（点名） / 混合（"其中 X 个会退回，另外 Y 个将被真正删除：40 41 42"）。
- 点名列表用 `normalize` 压缩（连号收成区间、空格分隔）；超过 80 字只列前 12 个，后面写"…（共 N 个）"，
  否则长列表会把确认框撑出屏幕。
- 无论哪种情况都仍要二次确认（有来路的"删除"实际是退回，用户也可能点错）。

## 5. 踩过的坑（移植时最容易重犯，逐条对照）

| # | 现象 | 根因 | 正确做法 |
|---|---|---|---|
| 1 | 重叠棚时手动填的料量被改写，只能从平均值反算 | 重算派生值的过程先把棚数改回"本行自己数的个数"，覆盖改回来时被当成"用户改了棚数" | 先做覆盖再算派生；`setShedNumber` 会顺带算棚数，**比较前必须先存 oldCount** |
| 2 | 转入后目标行有号但棚数仍 0、料量不重算 | `remove` 只删独立数字，`1-40` 这种区间一字未动 | 区间必须可拆；转移要按号码集合换主人 |
| 3 | 转入偶尔目标行 0 棚 | 先写目标再扣来源，中间态两行同时占号，后行优先把号判回来源行 | **先扣来源，再写目标**；收尾强制重算 |
| 4 | 从第 2 行转回第 1 行后再也转不回第 2 行 | "落在目标行最小~最大之间就不写"的暗规则 + 幽灵号 | 删掉暗规则；转移后把两行重写成实际拥有 |
| 5 | 输入 `16-40` 打一半，别的行的 `4-15` 永久消失 | 半成品 `16-4` 被兜底解析成 4~16，边打字边改写 | 编辑快照 + 每字符从快照重推 |
| 6 | 换格瞬间行错位、字被提交到别的行 | `begin()` 先回调 `onCellEditEnd` 再落新行号，同步删行会让新格开到旧行号 | 删行一律 `post` 到本轮交互之后；浮层行号按删除下标平移 |
| 7 | 号被占走后，后行改小也回不来 | 覆盖把原文改写了，信息已经丢了 | 声明 / 显示两层，覆盖只改显示 |
| 8 | 删除后号又冒出来、料量没少 | 0.3.14 曾以为"上面那行还声明着"是 bug，改成全表剔除 | 那是**退回**，不是 bug：删除只动本行申明；要区分"退回"和"真删"，在确认框里点名真删的号（4.6） |
| 9 | 弹窗左边缘对不上棚数格 | 算完宽度右边放不下就整体左移 | 左边缘钉死，放不下就**缩宽度**（号码多换几行），只有右侧剩不到 120dp 才退回左移 |
| 10 | 整行转到空行时屏幕闪一下却没变化 | 等价于把整行下移一格，来源行被回收 | `pointlessWholeRowMove` 直接拒绝 |
| 11 | 2 个连号被压成 `1-2` | 压缩阈值拍成 2 | 阈值 3：连续 ≥3 才写区间 |
| 12 | 几行同时该回收，却"按一下键盘进一行" | 回收判定读 `getShedCount()` 缓存，失焦时缓存还没刷新，只认出一个死行 | 判定一律按声明文本重算；一次结算一次删完 |

## 6. 移植到 HarmonyOS（ArkTS）

### 6.1 分层与对应关系

模型层是纯逻辑、几乎零平台依赖，建议先原样搬过去；UI 层按 ArkUI 重写。

| Android | HarmonyOS | 说明 |
|---|---|---|
| `model/ShedCoverage.java` (190 行) | `model/ShedCoverage.ets` | 纯函数，1:1 直译；`TreeSet` → `Set<number>` + `Array.sort` |
| `model/ShedText.java` (186 行) | `model/ShedText.ets` | 同上；正则语法一致 |
| `model/ShedDisplay.java` (216 行) | `model/ShedDisplay.ets` | 纯函数；只做字符串，不量像素 |
| `model/ShedDraft.java` (70 行) | `model/ShedDraft.ets` | 纯函数 |
| `model/RowSettlement.java` (104 行) | `model/RowSettlement.ets` | 依赖 `FeedData` 接口 |

| JUnit | `@ohos/hypium` | 第 7 章的验收用例可直接改写成断言 |

### 6.2 建议移植顺序

1. `ShedCoverage` → `ShedText` → `ShedDisplay` → `ShedDraft`（纯函数，先跑单测，和 Android 版逐用例对齐）；
2. `FeedData` 加 `shedDisplay` 字段（不落盘）+ `setShedNumber` 清空显示；
3. 页面里的 `applyShedCoverage`：只写显示、写棚数、按需重算派生；
4. 编辑生命周期：快照 + 逐字符重推 + 结束清快照（**清快照必须在定稿重算之前**）；
5. 气泡：选中态、⋮ 菜单、待转池、转入/删除；
6. 行回收 + `post` 时序；
7. 展示态两行折叠接进表格绘制。

### 6.3 ArkTS 侧容易踩的点

- **快照必须是深拷贝的字符串数组**，ArkTS 的数组赋值是引用，直接 `base = snapshot` 会被就地改坏。
- `Set`/`Map` 迭代顺序在 ArkTS 里同样是插入序，但**不要依赖**它，输出前统一排序。
- 大整数解析：`parseInt('08')` 行为一致，但空串/非数字要先过滤（本文所有实现都用"只留数字字符"再 parse）。
- `JSON.parse` 得到的对象字段可能缺失，`shedDisplay` 永远不要从存储里读。
- 长文本测量宽度：`ShedDisplay` 不量像素，只按字符数算，所以两边的换行结果天然一致——**不要**在鸿蒙侧改成按 `measureText` 折行，会跑偏。
- 单元格绘制里 `…` 与数字紧贴时不要额外加空格，否则 9 字符预算算不准。
- `onChange` 里改数据要避免"改数据 → 触发 UI 刷新 → 再次 onChange"的回环，用 `suppress` 或比较新旧值。

## 9. 三句话版本（给未来的自己）

1. **棚数只认打点覆盖**（后行优先），任何"本行文本自己数"的结果都不能当权威。
2. **声明与显示分离**：覆盖只改显示，原文不动——这是"退回来源行"和"无幽灵号"同时成立的唯一办法。
3. **编辑期用快照重推**，不要在上一次结果上累积；删行一律 `post` 到本轮交互之后。
